# Аудит надёжности генерации презентаций

Дата: 25 сентября 2026 года
Проверенная ветка: `codex/fix-source-grounded-generation` (`ed4393f`)

## Вывод

Текущая проблема — не один сбой модели, а сочетание трёх независимых отказов. Последний коммит добавил полезную проверку происхождения данных, отчёт о покрытии источников и сетевые повторы, но одновременно сделал генерацию all-or-nothing: ошибка одного слайда или одного варианта останавливает всю колоду.

Полностью откатывать `ed4393f` не стоит. Следует оставить отчёты, проверку готового PPTX и сетевые повторы, но точечно вернуть деградацию на уровне одного слайда, восстановить двухшаговый агентный цикл и устранить предположения о структуре notes master.

Поддерживаемую цель лучше формулировать как «обработать любой структурно валидный, незашифрованный PPTX в заявленных пределах», а не буквально любой файл. Повреждённые, зашифрованные и неподдерживаемые презентации должны отклоняться до запуска генерации с понятным объяснением.

## Подтверждённые причины

### P0. Любая цифра ошибочно считается фактом, требующим источника

Последние задания:

- `7515e3cee1f34554a0f3c3748ed35cb1`;
- `6d162bad362044478d51e08e3cfaecb7`.

Оба имеют `source_count: 0` и падают на первом слайде с сообщением «на слайде есть цифры, а source_note не указан». При этом тема — Dota 2: цифра является частью имени продукта, а не статистическим утверждением. В структуре также есть служебные числа вроде «колонка 1», «4 элемента» и «1 схема».

Причины в коде:

1. `slide_spec_problems()` в `src/deckforge/plan/spec.py` требует `source_note` для любого символа-цифры без классификации контекста.
2. Бриф используется при построении структуры, но в `write_slides()` как `sources` передаются только вложенные источники. При `source_count: 0` модель не получает текст брифа как материал с провенансом.
3. Исправляющий запрос `_ask_slide_writer()` получает список ошибок, но не получает предыдущий JSON слайда. Модель пишет новый ответ с нуля и закономерно повторяет ошибку.
4. Наличие произвольной строки `source_note` проверяется, но сама строка не доказывает, что число действительно есть в источнике. Формальная проверка одновременно слишком строгая для `Dota 2` и слишком слабая для выдуманного KPI.
5. `JobStore` запускает API с `allow_offline_fallback=False`; тот же флаг запрещает не только работу без провайдера, но и локальную деградацию одного невалидного ответа. В результате один слайд обрывает всю презентацию.

### P0. Сборщик предполагает наличие текстового фрейма заметок

Задание `6393268a9b764ed38ec79eac69afbecc` успешно получило восемь модельных слайдов, но все варианты упали с `'NoneType' object has no attribute 'text'`.

Сбой воспроизведён на сохранённых артефактах и шаблоне `07aa33a35e014735b03137116500e2f7` (`Набор_и_правка_простого_текста_Гавриков.pptx`) для `dense`, `airy` и `visual`:

```text
src/deckforge/compose/builder.py:216
slide.notes_slide.notes_text_frame.text = text.strip()
AttributeError: 'NoneType' object has no attribute 'text'
```

У этого валидного шаблона notes master не предоставляет ожидаемый body placeholder. Сборщик должен проверять `notes_text_frame`, уметь создать безопасный текстовый блок заметок либо пропустить заметку с диагностикой. Ошибка заметок не должна уничтожать уже собранный слайд.

### P0. Невалидный JSON структуры не ремонтируется

Задание `832d866855f9483b844d10105ba1a850` завершилось на outline:

```text
модель вернула обрезанный или невалидный JSON (finish_reason=stop):
Expecting ',' delimiter: line 1 column 2002
```

Сетевые/JSON-повторы добавлены для slide writer через `_complete_with_transient_retry()`, но `build_outline()` продолжает вызывать `llm.complete()` напрямую. При `finish_reason=stop` бюджетная эскалация провайдера не срабатывает, а repair-запроса для структуры нет.

### P1. Конфигурация противоречит prompt агента

`agents/slide-writer/AGENT.md` описывает дополнительный шаг для инструментов `check_number`, `measure_fit`, `list_layouts` и `try_slide`. Однако `config/app.yaml` и `AGENT_MAX_STEPS_DEFAULT` установлены в `1`.

Следствие: единственный шаг сразу помечается как финальный, инструменты запрещены, а инструкции по самопроверке фактически недоступны. До `ed4393f` значение было `2`.

### P1. Один вариант отменяет остальные

`_run_job()` создаёт три варианта в одном `asyncio.TaskGroup`. Необработанное исключение одного варианта отменяет соседние задачи. Пользователь не получает даже те варианты, которые могли успешно собраться.

Нужен статус `done_with_warnings`/`partial`: каждый вариант сохраняет собственную ошибку, а задание считается неуспешным только если не собран ни один вариант.

### P1. Наблюдаемость недостаточна

`generation-report.json` сохраняет только короткий текст исключения. Для ошибки сборки не указаны вариант, слайд, шаблон, функция и stack trace. Полный trace должен оставаться в серверном логе, а безопасный отчёт — содержать `stage`, `variant`, `slide_index`, `exception_type`, `attempt` и путь к диагностическому артефакту.

### P1. Зелёные тесты не покрывают реальные отказы

Проверка `tests/plan/test_writer.py`, `tests/api/test_api.py` и `tests/compose/test_builder.py` проходит: **84 passed**. Это подтверждает, что дефекты находятся вне текущей матрицы:

- API-тест использует детерминированный провайдер, который всегда корректно заполняет `source_note`;
- нет кейса с названием, содержащим цифру, при пустом списке источников;
- нет интеграционного теста на шаблоне без notes body placeholder;
- нет outline repair для невалидного JSON с `finish_reason=stop`;
- нет теста частичного успеха трёх вариантов.

## Рекомендация по откату

Не делать полный `git revert ed4393f`: он удалит полезные отчёты, проверку покрытия, проверку потерь в PPTX и сетевые повторы.

Сделать целевой rollback поведения:

1. Вернуть `slide_writer_agent_max_steps: 2`.
2. Разделить `require_provider` и `allow_slide_fallback`: отсутствие AI по-прежнему останавливает создание до старта job, но два невалидных ответа одного слайда переводят только этот слайд в контролируемую деградацию.
3. Не откатывать `generation-report.json`, `validate_deck_content()` и `validate_pptx_content()`; расширить их typed-диагностикой.
4. Не принимать fallback как готовый качественный результат: помечать колоду `done_with_warnings`, показывать пользователю проблемные слайды и разрешать их перегенерировать.
