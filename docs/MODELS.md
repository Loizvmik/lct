# Модели

Организаторы просили указать сервис, модель и настройки. Ниже всё это,
взятое из `config/app.yaml` (версия 1.12.1), `config/models.yaml` и
констант `provider/yandex.py`.

## Сервис

**Yandex Cloud AI Studio**, OpenAI-совместимый API:

- эндпоинт `https://llm.api.cloud.yandex.net/v1/chat/completions`;
- модель адресуется как `gpt://<YANDEX_FOLDER_ID>/qwen3.6-35b-a3b/latest`;
- авторизация заголовком `Authorization: Api-Key <YANDEX_API_KEY>`, ключ
  сервисного аккаунта с ролью `ai.languageModels.user`.

Ключ и id каталога читаются только из `.env` (шаблон `.env.example`).
Если они окажутся в `config/app.yaml`, загрузка настроек падает с ошибкой.
Локального инференса нет, веса не скачиваются. Клиент в
`src/deckforge/provider/yandex.py`, смена провайдера сводится к новому
классу с тем же интерфейсом (`complete`, `ask_image`).

## Модель

**`qwen3.6-35b-a3b`**, [Qwen/Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)

| | |
|---|---|
| Лицензия | Apache-2.0 |
| Параметров | 35B, Mixture-of-Experts |
| Активных на токен | 3B |
| Мультимодальность | да: текст и изображения |
| Рассуждения | есть, управляются `reasoning_effort` |

Одна модель на все роли: и текст, и вопросы по картинке слайда. Выбор
простой: из двух моделей реестра, прошедших ограничения ТЗ, только она
понимает изображения, а аудит по картинке и разбор шаблона по превью без
этого невозможны. MoE с 3B активных параметров
отвечает быстро, что важно при десятках вызовов на презентацию.

Особенности, под которые настроен клиент: рассуждения съедают бюджет
токенов; бывает пустой или не-JSON ответ с `finish_reason=stop`; модель
любит оборачивать JSON в markdown.

## Реестр моделей и проверка

`config/models.yaml` перечисляет допущенные модели с лицензией, размером,
мультимодальностью и ролями, а в разделе `denied` запрещённые с причиной.
`provider/registry.assert_allowed` вызывается при создании клиента, до
первого HTTP-запроса:

- модель из `denied` не вызывается (`gpt-oss-120b` и `qwen3-235b-a22b-fp8`
  больше 35B; `yandexgpt-5-pro`, `yandexgpt-5-lite`, `aliceai-llm`,
  `deepseek-v4-flash` без открытой лицензии);
- модель, не описанная в реестре, тоже не вызывается: отсутствие записи не
  считается разрешением;
- лицензия обязана быть Apache-2.0 или MIT, размер не больше 35B.

Запасная модель в реестре: `gpt-oss-20b` (Apache-2.0, 21B, без картинок).
Роль переключается правкой `llm.roles.<роль>` в `config/app.yaml`, без
кода. По умолчанию все роли на `qwen3.6-35b-a3b`.

Проверку держат тесты `tests/test_provider_registry.py`.

## Роли и настройки

Каждая роль: свой промпт `agents/<агент>/AGENT.md` (версия во
фронтматтере) и своя строка в `llm.roles`.

| Роль | Агент (версия) | Что делает | Рассуждения | max_tokens старт / потолок | Температура | Параллельно |
|---|---|---|---|---|---|---|
| `outline` | `outline-writer` 1.4.0 | структура колоды, один вызов на три стиля | none | 6144 / 7168 | 0,3 | 1 |
| `writer` | `slide-writer` 3.6.0 | текст слайда под контракт, до 2 шагов с инструментами | none | 6144 / 16384 | 0,3 | до 6 на задание |
| `writer` (починка) | `slide-writer` | сокращение текста под раскладку во время сборки | none | как у писателя | 0,3 | по одному, до 4 на колоду |
| `photo_picker` | `photo-picker` 1.1.0 | фото пользователя по пунктам структуры, до планирования (CLI, API, интерфейс) | none | 2048 / 7168 | 0,3 | 1 |
| `content_audit` | `content-auditor` 1.3.0 | C01-C11 и оценки 1-5 по картинке | none | 20480 на слайд, 40960 на колоду | 0,0 | по очереди модели |
| `palette_namer` | `palette-namer` 1.0.0 | имена ролей палитры при разборе | по умолчанию модели | 6100 / 7168 | 0,3 | 1 |
| `pattern_kind` | `pattern-kind-vision` 2.0.0 | вид раскладки по превью при разборе | по умолчанию модели | 3072 на раскладку / 7168 | 0,0 | 8 |
| `pattern_schema` | `pattern-schema` 1.1.0 | схема слотов раскладки при разборе | по умолчанию модели | 7168 | 0,0 | 4 |

Роли разбора шаблона работают до пятиминутного бюджета, их ответы лежат в
кэше профиля, и уровень рассуждений у них не менялся намеренно.

**Почему писатель без рассуждений.** Замер на трёх стилях: с
рассуждениями писатель отвечал 24 с на вызов и в 17 вызовах из 47
упирался в потолок токенов, все три задания уходили в режим EMERGENCY.
С `reasoning_effort: none` тот же запрос отдаёт тот же JSON за 0,7-3 с.
Качество держит не рассуждение, а контракт и проверка кодом после ответа.
Аудит по картинке с уровнем low шёл 30 с на слайд, это чек-лист, и он
тоже переведён на none. Структура тоже без рассуждений (версия конфига
1.12.1): с `low` на наборе `full-coverage` (6 КБ источников) она дважды
из двух сжигала весь `max_tokens` на рассуждения за 44-60 с и молча
уходила в запасной скелет с пунктами «Дополнительный контекст»; с `none`
тот же запрос отдаёт 15 пунктов с формами `kpi`, `table`, `chart`,
`quote` за 4-10 с.

Итог в `llm.reasoning`: `outline`, `writer`, `photo_picker`,
`content_audit` и неиспользуемый `pattern_picker` на `none`.

**Общие настройки вызова** (`llm` в `config/app.yaml`, `provider/yandex.py`):

| Параметр | Значение | Зачем |
|---|---|---|
| `deadline_seconds` | 60 | потолок одного вызова по часам, включая ретраи и эскалации; дополнительно режется по остатку бюджета задания |
| HTTP-ретраи | 4 попытки на 429, 500, 502, 503, 504 | сетевые сбои не роняют слайд |
| Эскалация бюджета | до 2 удвоений `max_tokens`, не выше потолка роли | ответ ушёл в рассуждения и обрезан (`finish_reason=length`) |
| Повтор «только JSON» | 1 раз | пустой или не-JSON ответ при `finish_reason=stop` |
| `model_concurrency` | 6 на процесс | при 12 одновременных Yandex отвечал 429 |
| `slide_writer_agent_max_steps` | 2 | шаги агентного цикла писателя |
| `pattern_kind_max_workers` | 8 | параллелизм разбора |
| `pattern_schema_max_workers` | 4 | при 8 половина вызовов получала 429 |

Очередь (`provider/scheduler.py`) выдаёт 6 слотов сначала по классу стадии
(структура и текст, затем починка, затем аудит по картинке), потом по
времени до резерва задания, между заданиями поровну.

## Модель предлагает, код проверяет

- Ответ разбирается по JSON-схеме; не разобрался: запасной путь или
  находка, но не исключение.
- Структура: вид пункта только из закрытого списка, невалидный пункт
  отбрасывается.
- Текст: проверяется контракт слайда (обязательные места, пределы слов,
  недобор) и числа по источникам (`check_number`).
- Вид раскладки: только из переданного списка.
- Схема слотов: флаги принимаются от уверенности 0,8, описание от 0,5.
- Палитра: предложенный цвет обязан быть во входной палитре.
- Фото: имя не из присланных отвергается, одно фото на двух слайдах тоже,
  слайду с кодом фото не назначается.
- Код на слайде модель не пишет: он идёт дословно из fenced-блока
  источника, писатель даёт только заголовок и подпись.
- Аудит по картинке: невалидный ответ становится находкой `C00` с сырым
  текстом ответа.

## Без ключа

Без `.env` пайплайн не падает, каждая роль идёт запасным путём:

| Роль | Запасной путь |
|---|---|
| `outline` | типовой скелет структуры на целевое число слайдов, данные источников всё равно размечаются кодом |
| `writer` | слайд из пунктов структуры, график по данным источника, пометка в заметках докладчика |
| `photo_picker` | фото не размещаются, о каждом предупреждение с причиной |
| `content_audit` | пропуск с явной причиной `skipped_reason`, детерминированный аудит идёт полностью |
| `palette_namer` | частотный анализ и HSV |
| `pattern_kind`, `pattern_schema` | вид по геометрии, схема слотов пустая, контракт по вместимости |

`deckforge bench --offline` гоняет весь путь так и даёт нижнюю планку
качества.

## Сколько вызовов на презентацию

Одно задание (один стиль, 12 слайдов, режим FULL), по снимку задания:

| Роль | Вызовов |
|---|---|
| структура | 1 (общая на три стиля) |
| писатель | около 20: по вызову на слайд, плюс шаги с инструментами и ремонты по контракту |
| починка при сборке | около 4 (предел 4) |
| аудит по картинке | 6-10: до 6 рискованных слайдов плюс вызов на колоду целиком (C09, C11) и повторы невалидных ответов |

Итого 30-35 вызовов на презентацию, 90-100 на три стиля. Разбор
незнакомого шаблона добавляет по вызову на паттерн (вид и схема, десятки
вызовов) и один на палитру, но один раз на файл и вне лимита 5 минут.

## Неиспользуемые промпты

`agents/pattern-picker` (роль `pattern_picker`) и `agents/slide-realizer`
остались от прежней схемы, где модель выбирала раскладку и переписывала
готовый текст под вариант. Теперь раскладку выбирает планировщик без
модели, и пайплайн эти промпты не вызывает. Параметры
`llm.pattern_picker_*`, `plan.rerank_variants` и `plan.realize_*` в
`config/app.yaml` тоже не действуют.
