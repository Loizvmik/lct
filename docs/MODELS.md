# Модели

Реестр моделей, допущенных к использованию, лежит в
[`config/models.yaml`](../config/models.yaml) и проверяется кодом
(`deckforge.provider.registry.assert_allowed`) до первого сетевого запроса:
лицензия обязана быть Apache-2.0 или MIT, размер — не больше 35B параметров.
Модель, не описанная в реестре или не прошедшая проверку, не будет вызвана —
`ModelNotAllowed` бросается раньше, чем уйдёт HTTP-запрос. Этот документ
собран из `config/models.yaml`, чтобы не разойтись с кодом.

## Основная модель

**`qwen3.6-35b-a3b`** — [Qwen/Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)

| | |
|---|---|
| Лицензия | Apache-2.0 |
| Параметры | 35B, MoE (3B активных на токен) |
| Мультимодальность | да (vision) |
| Провайдер | Yandex Cloud AI Studio (OpenAI-совместимый эндпоинт) |
| Роли | outline, writer, pattern_picker, palette_namer, content_audit |

Единственная из двух зарегистрированных моделей с vision — поэтому именно
она обслуживает роль `content_audit` (одиннадцать вопросов модельного
аудита по картинке слайда, C01–C11), которую текстовая модель отработать не
может физически.

## Запасная модель

**`gpt-oss-20b`** — [openai/gpt-oss-20b](https://huggingface.co/openai/gpt-oss-20b)

| | |
|---|---|
| Лицензия | Apache-2.0 |
| Параметры | 21B |
| Мультимодальность | нет |
| Провайдер | Yandex Cloud AI Studio |
| Роли | outline, writer, pattern_picker, palette_namer |

Без vision — не участвует в роли `content_audit`. Переключение роли на эту
модель делается правкой `config/app.yaml` (`llm.roles.<роль>`), без правки
кода — модель на роль разнесена по конфигу заранее именно ради этого.

## Пять ролей конвейера

Каждая роль — отдельный промпт-файл с версией во фронтматтере в `agents/`,
подхватываемый по имени роли (`model_role` в фронтматтере файла ↔
`llm.roles.<роль>` в `config/app.yaml`). Промпты не зашиты в код.

| Роль (`model_role`) | Файл промпта | Что делает | Модель вызывается |
|---|---|---|---|
| `outline` | [`agents/outline-writer/AGENT.md`](../agents/outline-writer/AGENT.md) | Структура колоды: сколько слайдов, о чём каждый, в каком порядке | `plan/outline.py` |
| `writer` | [`agents/slide-writer/AGENT.md`](../agents/slide-writer/AGENT.md) | Текст одного слайда по пункту структуры и источникам | `plan/writer.py`, параллельно по слайдам |
| `pattern_picker` | [`agents/pattern-picker/AGENT.md`](../agents/pattern-picker/AGENT.md) | Выбор конкретной раскладки шаблона под содержание слайда среди уже отфильтрованных кодом кандидатов | `plan/writer.py::pick_patterns` |
| `palette_namer` | [`agents/palette-namer/AGENT.md`](../agents/palette-namer/AGENT.md) | Присвоение частотным цветам шаблона семантических ролей дизайн-системы (`brand`/`surface`/`on_surface`/...) | `template/naming.py` — единственное место `template/`, вызывающее модель |
| `content_audit` | [`agents/content-auditor/AGENT.md`](../agents/content-auditor/AGENT.md) | Одиннадцать да/нет-вопросов о слайде по его изображению | `audit/visual.py`, только `deckforge audit-visual` |

Во всех пяти ролях действует один принцип — **модель предлагает, код
проверяет**: ответ валидируется схемой (`plan.spec.slide_spec_problems`,
`_parse_answer` в `audit/visual.py` и т. д.), предложенный моделью цвет
обязан присутствовать во входной палитре, предложенная раскладка — среди
уже отфильтрованных кодом кандидатов. Без ключа/секретов в `.env` каждая
роль откатывается на детерминированный запасной вариант (частотный анализ +
HSV для палитры, ранжирование по замеренной вместимости для раскладки) —
пайплайн не падает, но качество текста и подбора хуже.

## Системные требования

Обе модели работают через Yandex Cloud AI Studio (`YANDEX_FOLDER_ID` +
`YANDEX_API_KEY` в `.env`) — локального инференса нет, веса на диск не
скачиваются. Локально нужен только сетевой доступ к
`https://llm.api.cloud.yandex.net`.

Дедлайн одного вызова модели — 60 секунд по wall-clock
(`config/app.yaml`, `llm.deadline_seconds`), считает и HTTP-ретраи, и
эскалацию бюджета `max_tokens` вместе (`provider/yandex.py`). Число слайдов,
чей текст пишется одновременно, — 4 (`llm.slide_writer_max_workers`);
столько же используется параллелизмом в модельном аудите по картинке
(`audit.visual.run_visual`, `--max-workers`).

## Отвергнутые модели

Из `config/models.yaml`, раздел `denied` — с причиной отказа рядом с
каждой записью, не в отдельном месте:

| Модель | Причина |
|---|---|
| `gpt-oss-120b` | 120B превышает потолок 35B из ТЗ |
| `qwen3-235b-a22b-fp8` | 235B превышает потолок 35B из ТЗ |
| `yandexgpt-5-pro` | закрытая лицензия, ТЗ требует Apache 2.0 / MIT |
| `yandexgpt-5-lite` | закрытая лицензия, ТЗ требует Apache 2.0 / MIT |
| `aliceai-llm` | закрытая лицензия, ТЗ требует Apache 2.0 / MIT |
| `deepseek-v4-flash` | закрытая лицензия, ТЗ требует Apache 2.0 / MIT |

Реестр закрытый: модель, отсутствующая и в `models`, и в `denied`, тоже не
будет вызвана (`assert_allowed` требует явного описания лицензии и размера
для каждой используемой модели, отсутствие записи — не разрешение по
умолчанию).
