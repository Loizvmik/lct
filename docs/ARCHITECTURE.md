# Архитектура DeckForge

Документ для жюри. Всё ниже взято из кода ветки `feat/deckforge`; числа
сверены с `config/*.yaml` и константами модулей.

## Главная идея

Шаблон жюри незнаком, модель на 35B параметров путается в координатах, а
на презентацию есть 5 минут. Поэтому обязанности разделены жёстко:

- **код решает, как выглядит слайд**: какая раскладка, где фигура, какой
  кегль и цвет. Всё это снимается с самого шаблона;
- **модель решает, что сказано**: структура, текст под заданные пределы,
  проверка смысла по картинке. Координат, цветов и кеглей она не видит и
  не возвращает;
- **любой ответ модели проверяет код**, а на любой отказ модели есть
  запасной путь без неё.

Порядок работы: сначала композиция всей колоды, потом текст под неё. Когда
текст писался раньше раскладки, нарядные раскладки шаблона (36-84 знака на
место) отклоняли текст на 140-200 знаков, и визуальный вариант выходил
белыми листами.

```
шаблон .pptx ──► разбор (template/) ──► TemplateProfile (кэш)
                                              │
бриф + источники ──► структура (модель, одна на три стиля)
                                              │
               ┌──────────────────────────────┼─────────────── по стилю, параллельно
               ▼                              ▼
   типы данных источников         планировщик раскладок (pattern/)
   (график / показатель / таблица)  лучевой поиск по всей колоде, без модели
               └──────────────► контракт слайда (plan/contracts.py)
                                              │
                              текст под контракт (модель, параллельно по слайдам)
                                              │
                              сборка клоном примера + лестница починки (compose/)
                                              │ аудит L01-L04, D05 в цикле
                              аудит колоды + автопочинка (audit/)
                                              │
                              экспорт .pptx / .pdf / .html + превью
                                              │
                              аудит по картинке рискованных слайдов (модель)
```

## Слои и границы

| Пакет | Что делает | Граница |
|---|---|---|
| `ooxml/` | zip, части, связи, обход фигур с групповыми преобразованиями, цвета темы, геометрия в долях холста | без модели |
| `template/` | разбор шаблона в `TemplateProfile` | модель только в `naming.py` (имена ролей палитры) и `vision_kind.py` (вид и схема раскладки по картинке) |
| `pattern/` | намерение слайда, возможности раскладки, стоимость, лучевой поиск | без python-pptx, без координат, без модели |
| `plan/` | структура, типы данных, контракт, текст, нормализация | без python-pptx и координат; модель в `outline.py`, `writer.py`, `photos.py` |
| `compose/` | сборка `.pptx`: клон, привязка текста, подгонка, графики, таблицы, с нуля | модель не зовёт; починка текста приходит снаружи готовым объектом |
| `audit/` | детерминированные проверки, автопочинка, риск, аудит по картинке, верность шаблону | модель только в `visual.py` |
| `workflow/` | бюджет времени, режимы, починка, стадия аудита по картинке, версии | склеивает слои |
| `provider/` | клиент Yandex, реестр моделей, общая очередь вызовов | единственное место с HTTP |
| `render/`, `export/` | LibreOffice (pdf, png), HTML-отчёт, бандл | без модели |
| `api/`, `web/`, `cli.py` | FastAPI, Next.js, командная строка | оба входа идут одними функциями |

Границы проверяются тестами на уровне AST, а не договорённостью:

- `tests/plan/test_no_pptx_import.py`: `plan/` не импортирует python-pptx;
- `tests/pattern/test_layers.py`: `pattern/` и `plan/contracts.py` без
  python-pptx, без обращений к координатам (`.box`, `.left`...) и без
  вызовов `complete`/`ask_image`;
- `tests/template/test_architecture.py`: в `template/` модель зовут только
  `naming.py` и `vision_kind.py`;
- `tests/test_no_hardcoded_prompts.py`: в Python нет строк-промптов, все
  промпты лежат в `agents/*/AGENT.md` с версией во фронтматтере.

Каждый тест границы содержит проверку самой проверки: подложенное
нарушение обязано ловиться.

## Разбор шаблона

Результат: `TemplateProfile`, JSON. Разбор идёт один раз на файл, до
пятиминутного бюджета (90-280 с на незнакомом шаблоне, потом из кэша за
доли секунды).

**Дизайн-система.** Гарнитуры (до двух), шкала кеглей по фактическому
употреблению на слайдах-примерах (ступени micro, caption, body, h2, h1,
display), палитра с ролями (brand, accent, text, background...; имена
ролей даёт модель, без неё частотный анализ и HSV), сетка (поля и оси,
восстановленные по положению фигур, плюс явные направляющие), каталог
ассетов (логотип, фоны, иконки, картинки), палитра рядов графика из
цветных токенов шаблона с контролем различимости (ΔE в CIE Lab).

**Паттерны вместо макетов.** В реальных шаблонах плейсхолдеры макетов
покрывают 4-24% фигур, остальное свободные фигуры на слайдах-примерах.
Поэтому единица разбора: паттерн, композиция, снятая со слайда-примера
(`template/patterns.py`):

1. обход фигур с групповыми преобразованиями, деление на содержание и
   декор (линии, плашки без текста, логотип, фон);
2. роль каждого места по типографической ступени, положению и виду
   текста: `headline`, `subhead`, `body`, `bullet`, `card_title`,
   `card_body`, `kpi_value`, `kpi_label`, `caption`, `source`, `image`,
   `icon`, `table`, `chart`;
3. повтор (`RepeatSpec`): регулярная сетка одинаковых единиц (карточки,
   шаги, показатели), в том числе двумерная; декор приписан к своей
   единице, чтобы при меньшем числе карточек лишние кружки уходили вместе
   с ними;
4. вид раскладки геометрией; если геометрия не уверена (ниже 0,8), модель
   уточняет вид по картинке примера, выбирая только из переданного списка;
5. вместимость каждого места по реальным метрикам шрифта (Pillow по файлу
   шрифта), плотность самого примера (`source_density`);
6. отсев: качество ниже 0,35, больше 60 фигур декора (лист иконок),
   моноширинный текст (примеры кода), нет заголовка у не-героической
   раскладки; похожие примеры схлопываются.

**Классы слайдов** (`template/prototypes.py`): `content_pattern`,
`style_guide`, `asset_sheet`, `visual_prototype`, `instruction`.
Планировщик ставит под содержание только первый класс; «Пример оформления
графика» или «схема из блоков-рыб» раскладкой содержания не станут.

**Образцы графиков.** Если в шаблоне нет родных диаграмм, но есть картинки
графиков, из них снимается `ChartStylePrototype`: рамка, палитра с самой
картинки, сетка, подписи значений. Правила, написанные текстом («Перекрытие
рядов = ±50%, боковой зазор 0%, без линий сетки», VK Education, слайд 51),
читаются `template/chart_rules.py` и применяются к нашему графику.

**Схема слотов от модели.** Каждому паттерну модель по превью и манифесту
мест даёт `purpose`, `content_hint`, `max_words`, `ordinal` (порядковый
номер, текст не менять), `fixed` (постоянный текст шаблона) и уверенность.
Код принимает флаги `ordinal`/`fixed` при уверенности от 0,8, описание от
0,5; `fixed` только для фраз до 4 слов без подсказок дизайнера
(«вставьте», «пример»); в слоте заголовка постоянного текста не бывает.

**Кэш с отпечатком** (`template/profile.py`). Две части с отдельными
версиями: детерминированная (геометрия, паттерны,
`DETERMINISTIC_SCHEMA_VERSION = 5`) и модельная (виды, схема слотов, имена
палитры, `MODEL_SCHEMA_VERSION = 1`), общая версия `5001`. Ключ модельной
части: `sha256(шаблона)-v5001-m<отпечаток>`, где отпечаток хэширует id
моделей ролей разбора и тексты их трёх `AGENT.md`. Правка промпта
перезапрашивает модель, но не перемайнивает геометрию. Если кэш записан
без модели, а модель появилась, недостающие части дозапрашиваются.

## Структура и данные

**Структура** (`plan/outline.py`, агент `outline-writer`): один вызов на
пакет из трёх стилей. На вход бриф, источники, целевое число слайдов
(10-15, по умолчанию 12) и сводка форм, которые умеет шаблон. На выход
пункты: вид, мысль, факты, которые слайд обязан показать, особая форма
(`quote`, `kpi`, `table`, `chart`).

**Данные до текста** (`plan/series.py`, `plan/data_types.py`): код
читает из источников markdown-таблицы и списки «подпись: число» и
присваивает тип без модели:

| Тип | Признак | Как показать |
|---|---|---|
| `TimeSeries` | категории: кварталы, годы, месяцы | график обязателен от 4 точек, от 7 точек линия |
| `CategoryComparison` | категории не время | столбики, обязательны от 3 категорий |
| `PartToWhole` | части складываются в итог или 100% | накопительные столбики или круговая |
| `MetricSet` | одно-два числа | показатель |
| `TableData` | разные единицы в столбце или матрица больше графика | таблица |

Строка «Итого» в ряд не входит; столбец с разными единицами («12 минут»
и «18 часов») графиком не рисуется. Числа графика берутся из источника,
модель только подписывает и формулирует вывод.

## Планировщик раскладок

`pattern/`, детерминированно, миллисекунды на колоду.

**Намерение и возможности.** Для каждого пункта структуры
`SlideIntent` (форма, число единиц, есть ли фото, таблица, график), для
каждого паттерна `PatternForm` (главное место, единицы повтора, пределы
слов и знаков, декор, места под картинку, таблицу, график). Предел места
считается тем же замером, которым клон потом проверяет текст (реальный
кегль примера, рамка минус отступы, гарнитура), чтобы контракт и сборка не
расходились.

**Жёсткие ограничения** (`candidates.py`): вид совместим с формой
содержания; мест хватает под все блоки; обложка только первому слайду,
финальная раскладка («Спасибо», контакты, последний пример) только
последнему; раскладка с постоянным заголовком не для содержательных
слайдов; раскладка, где после удаления фото примера пустеет заметная
часть холста, без нашего фото не годится. Если кандидатов не осталось,
ограничения ослабляются по одному от наименее важного, причина пишется в
отчёт («в шаблоне нет раскладки нужной формы» и т. п.).

**Стоимость назначения** (`scoring.py`, веса в `config/styles.yaml`):

```
cost = overflow × 1000            доля содержания, которую раскладка не вмещает
     + consecutive_repeat × 500   тот же облик, что у соседа
     + 30 × 2^(n-1)               n-й повтор облика в колоде: 30, 60, 120...
     + style_mismatch × 20        вид не из предпочтений стиля
     + density_mismatch × 10      плотность примера далека от цели стиля
     + orphan_image × 15 + cover_miss × 50 + short_headline × 60
     + sample_photo_void × 200    пустота на месте фото примера
     + chart_fit × 25             место под график хуже родного
     - pattern_quality × 5 - decor_richness × decor_weight × 10
```

«Облик» (`look_key`) сравнивает вид, макет, роли мест, повтор и декор, а
не `pattern_id`: два примера с одной геометрией глаз читает как одну
раскладку.

**Ограничения разнообразия**: один облик не больше 3 раз на колоду и не
два раза подряд; карточки и списки не больше двух слайдов подряд.

**Лучевой поиск** (`planner.py`, ширина 20): держит 20 частичных колод и
сравнивает их целиком, поэтому может уступить лучшую раскладку одному
слайду, чтобы не повторить её у соседа. На выходе у слайда `pattern_id` и
до трёх запасных раскладок, они едут со слайдом до сборки.

**Стиль как целевая функция**: у `dense`, `airy`, `visual` свои
предпочтения видов, целевая плотность, слова на единицу и вес декора (см.
таблицу в README). `airy` вставляет разделители между разделами, `visual`
вдвое ценит графики.

## Контракт слайда и писатель

**Контракт** (`plan/contracts.py`): по выбранной раскладке код пишет
писателю числами, что нужно: заголовок до N слов, K карточек по M слов,
таблица до R строк, график с данными из источника. Цель места 0,8
предела. Для каждого места роль, назначение и подсказка из схемы слотов.
После ответа код проверяет тот же контракт: пропущенное обязательное
место, переполнение, сильный недобор.

**Писатель** (`plan/writer.py`, агент `slide-writer`): один вызов на
слайд, слайды пишутся параллельно. Ограниченный агентный цикл: до 2 шагов,
инструменты `measure_fit` (влезет ли текст, замер шрифтом) и
`check_number` (есть ли число в источниках). При нарушении контракта один
ремонтный вызов; его ответ принимается, только если нарушений стало
меньше. Пустой или не-JSON
ответ: запасной слайд из пунктов структуры с пометкой в заметках
докладчика. График запасного слайда строится по данным источника, модель
для него не нужна.

**Нормализация** (`plan/normalize.py`): одна карточка становится абзацем
или показателем; 1-2 коротких пункта с числами становятся показателями,
если у шаблона есть такая раскладка; слайд с одним пунктом, повторяющий
факт другого, выбрасывается.

## Сборка

`compose/builder.py`. Колода открывается из файла шаблона, слайды-примеры
убираются из списка, но их части остаются для клона.

**Клон примера** (`compose/clone.py`): копия дерева фигур слайда-примера
на тот же макет с переносом связей (картинки, диаграммы). Место паттерна
находит фигуру клона по `source_shape_id`. Текст подменяется с
сохранением форматирования первого run; фото пользователя подменяет
картинку в той же рамке (маска и скругление остаются); таблица встаёт в
родную таблицу примера; незаполненные единицы повтора удаляются вместе со
своим декором; текст примера, не привязанный к содержанию, удаляется.

**Графики.** Место под график выбирается одной функцией для планировщика
и сборки (`chart_target_slot`), по ступеням: родной график примера
(данные подменяются `replace_data`, оформление шаблона остаётся), рамка
картинки-образца графика, крупное текстовое место. График рисуется
нативным `c:chart` (столбики, в том числе накопительные и
горизонтальные, линия, круговая), цвета рядов явно из
палитры шаблона, правила оформления шаблона (зазор, перекрытие, сетка)
применяются.

**Подгонка кегля с пределом.** При переполнении кегль ужимается по шкале
шаблона (с промежуточными 40/36/32/28/24/20/18), но не ниже 0,8 от кегля
примера и не больше чем на две ступени. У заголовка обложки, разделителя и
финала 0,6 и четыре ступени. Глубже это отказ, а не успех: заголовок 44pt,
ужатый до 18pt, спасает текст ценой дизайна. Аудит судит тем же пределом
(T02).

**Лестница починки по причине отказа** (`compose/failure.py`, путь в
`config/app.yaml`, `compose.repair_policy`). Каждая неудачная попытка
называет причину, главная выбирает путь:

| Причина | Путь |
|---|---|
| `TEXT_OVERFLOW` | раскладка просторнее → сокращение текста моделью → разбиение на два слайда → с нуля |
| `MISSING_SLOT` | другая раскладка с местами под все блоки → с нуля |
| `TOO_MANY_UNITS` | раскладка с большим повтором → разбиение → с нуля |
| `LOW_DENSITY` | раскладка плотнее → лучший из пустоватых клонов |
| `OVERLAP`, `BUILD_ERROR` | другая раскладка → с нуля |
| `MODEL_FAILURE` | сокращение без модели до первых предложений |

После каждой попытки кандидат проверяется аудитом L01-L04 и D05; при
находке откат и следующая ступень. Сокращение моделью живёт в
`workflow/repair.py` (не больше 4 вызовов на колоду, в режиме EMERGENCY
выключено). Путь каждого слайда пишется в план и виден в отчёте.

**С нуля** слайд собирается в стиле шаблона: заголовок цветом и кеглем
заголовков примеров, текст не мельче body, декор по снятым фигурам.
Пустого слайда не бывает.

Заметки докладчика пишутся в notes slide. Версии всех промптов и
конфигов, которыми собран файл, пишутся в `docProps/custom.xml`
(свойство `deckforge_workflow`).

## Аудит

Подробно в [AUDIT.md](AUDIT.md). Коротко:

- 24 детерминированные проверки по XML готового файла (L, T, D, I), пять
  из них (L01-L04, D05) работают внутри лестницы сборки;
- у каждой находки класс починки: `local` (правит автопочинка),
  `structural` (нужен другой текст или раскладка), `none`;
- автопочинка 13 проверок одним проходом «аудит → патч → аудит»;
- аудит по картинке (C01-C11 и оценки PPTEval) только для рискованных
  слайдов: 6 в режиме FULL, 3 в FAST, 0 в EMERGENCY;
- метрики верности шаблону и редактируемости на каждую колоду.

## Бюджет времени и очередь модели

**Задание = одна презентация одного стиля.** `POST /api/decks/batch`
создаёт три задания с общей структурой: первое зовёт модель, остальные
ждут тот же результат. Стадии задания: parse (готов при загрузке шаблона)
→ outline → plan → write → compose → audit → export → visual_audit.

**`RunBudget`** (`workflow/budget.py`): 300 с на задание. Режим выбирается
целиком в контрольных точках (после структуры, после текста, после
сборки) по остатку времени:

| Режим | Остаток | Что разрешено |
|---|---|---|
| FULL | от 120 с | всё, аудит по картинке до 6 слайдов |
| FAST | от 75 с | аудит по картинке до 3 слайдов |
| EMERGENCY | меньше 75 с | только обязательные стадии, без сокращения текста моделью |

Резервы: писатель не начинает вызов, если после него останется меньше
60 с на сборку и экспорт; аудит по картинке не начинает вызов при остатке
меньше 45 с; за 30 с до конца незаконченные слайды уходят запасным путём, и
задание завершается статусом `done_with_warnings` с файлом.

**Очередь модели** (`provider/scheduler.py`): один лимит на процесс, 6
одновременных вызовов (при 12 Yandex отвечал 429). Слот выдаётся сначала
по классу стадии (структура и текст → починка → аудит по картинке), потом
по времени до резерва вызова: задание, у которого часы кончаются раньше,
получает слот первым. Между заданиями одного класса слоты делятся поровну.
Дедлайн вызова режется по остатку бюджета. Число вызовов по ролям и
ожидание в очереди пишутся в снимок задания и отчёт.

**Рассуждения по ролям.** Писатель с рассуждениями отвечал 24 с на вызов и
в 17 вызовах из 47 упирался в потолок токенов; без рассуждений тот же JSON
приходит за 0,7-3 с. Уровень задан по ролям в `config/app.yaml`
(подробно в [MODELS.md](MODELS.md)).

Замер 27 сентября на прогретом кэше: три стиля параллельно за 60-70 с при
лимите 300 с на каждый.

## Метрики

Чтобы сравнивать версии не глазами, у каждой колоды считаются числа
(`audit/fidelity.py`, `bench.py`):

- доля слайдов клоном и доля сохранённых фигур примера;
- отклонение геометрии текстовых фигур от мест паттерна;
- доля текстовых фигур без находок T01-T03 (типографика и палитра);
- разнообразие и нормированная энтропия раскладок;
- дельта плотности к примеру;
- доля родных ассетов шаблона;
- редактируемость: доля площади содержания, которую можно править в
  PowerPoint (текст, родная таблица, родной график, фото пользователя)
  против растра на месте содержания;
- находки по серьёзности, оценки по картинке, вызовы модели, ожидание
  очереди, режим, время.

`deckforge bench` снимает их на матрице шаблоны × наборы × стили,
`--compare` даёт дельты двух прогонов.

## Воспроизводимость

- Один конфиг на пайплайн (`config/app.yaml`), веса стилей
  (`config/styles.yaml`), пороги аудита (`config/audit.yaml`), реестр
  моделей (`config/models.yaml`); у каждого версия и история изменений в
  шапке.
- Промпты в `agents/*/AGENT.md` с semver; их версии и версии конфигов
  записаны в каждый собранный `.pptx`.
- Планировщик, сборка, детерминированный аудит и метрики детерминированы:
  одинаковый вход даёт одинаковый результат. Недетерминированы только
  ответы модели.
- Кэш профиля ключуется содержимым шаблона, версией схемы и отпечатком
  промптов разбора.
- 1066 тестов, модель в них не вызывается; `scripts/run.sh` и
  `scripts/setup_ubuntu.sh` поднимают всё с нуля.

## Как ведёт себя на незнакомом шаблоне

Ни одного сценария под конкретный шаблон в коде нет: всё, что знает
пайплайн о шаблоне, снято с его слайдов.

- **Разбор** идёт до бюджета. Если модель не ответила по паттерну, вид
  остаётся от геометрии, схема слотов пустая, контракт считается по
  вместимости мест. В профиле помечено, откуда взята каждая часть
  (`model`, `geometry`, `fallback`).
- **Бедный шаблон** (нет раскладки под таблицу, график, показатели):
  ограничения ослабляются по одному, причина пишется в отчёт; таблица или
  график рисуются в самом ёмком текстовом месте; в крайнем случае слайд
  собирается с нуля в стиле шаблона.
- **Нет родных графиков**: используется рамка картинки-образца и правила
  оформления из текста шаблона; нет и их: палитра шаблона и крупное место.
- **Шрифт шаблона не установлен**: замер идёт по метрически похожему
  шрифту с запасом ×1,15, это пишется в предупреждения профиля.
- **Модель недоступна или медленная**: запасной путь на каждом шаге,
  режимы бюджета жертвуют необязательным, файл есть всегда.

## Известные ограничения

- **Фото принимает только CLI** (папка `photos/` контент-пакета). В
  интерфейсе и API загрузки фотографий нет.
- **Схема слотов** у 1-3 паттернов из 33 остаётся без ответа: модель
  тратит бюджет на рассуждения, повтор с подсказкой «только JSON»
  помогает не всегда. Такие места пишутся по вместимости без подсказки.
- **Повторы фактов** убираются только у слайдов с одним пунктом;
  повтор числа в заголовках двух полных слайдов помечается и повышает риск
  слайда, но сам не переписывается.
- **Шрифты, сжатые MicroType Express** внутри `.pptx`, распаковать нельзя
  (закрытый формат сжатия). Их нужно поставить в систему вручную, иначе
  замер и рендер идут похожим шрифтом.
- **SmartArt не создаётся**: схемы собираются из нативных фигур и
  соединителей, в PowerPoint редактируются как обычные фигуры.
- **HTML-экспорт** не переносит картиночные и узорные заливки декора.
- **Генерация изображений моделью** (задача со звёздочкой) не делалась.
- **Реестр заданий в памяти процесса API**: перезапуск теряет прогресс
  идущих заданий, но не готовые файлы на диске.
- **Первый разбор незнакомого шаблона** занимает 90-280 с и в лимит
  5 минут не входит по условиям организаторов; его стоит сделать до
  демонстрации.
