# DeckForge

Берёт произвольный `.pptx`-шаблон, разбирает его на дизайн-систему, снимает
со слайдов-примеров внутри шаблона композиционные раскладки, по брифу и
исходным материалам планирует и пишет содержание, собирает презентацию на
макетах шаблона, проверяет её аудитом и выгружает в три формата (`.pptx`,
`.pdf`, `.html`). Веб-интерфейс на Next.js, бэкенд на FastAPI, командная
строка.

Дальше: [ARCHITECTURE.md](docs/ARCHITECTURE.md) — пайплайн и границы слоёв,
[MODELS.md](docs/MODELS.md) — модели и почему выбраны именно они,
[AUDIT.md](docs/AUDIT.md) — все 35 проверок аудита.

## Требования

- Python 3.12 (не 3.13 — `pyproject.toml` жёстко фиксирует `>=3.12,<3.13`) через [uv](https://docs.astral.sh/uv/).
- Node.js + [pnpm](https://pnpm.io/).
- [LibreOffice](https://www.libreoffice.org/) (бинарник `soffice`) — рендер `.pdf`/`.png`.
- `pdftoppm` или `pdftocairo` в `PATH` (обычно ставятся вместе с LibreOffice/poppler) — постраничный рендер PNG идёт через них, не напрямую через `soffice --convert-to png`.

## Сетап

```bash
uv sync --extra dev          # Python-зависимости, включая pytest
cp .env.example .env         # секреты модели — см. ниже
cd web && pnpm install && cd ..
```

## Переменные окружения

Единственная точка настройки самого пайплайна — `config/app.yaml` (модель на
роль, дедлайн вызова, параллелизм записи текста, пути кеша, путь к
`soffice`). Секреты в yaml не хранятся — они читаются только из `.env`
(`Settings.load` бросит ошибку, если найдёт `yandex_api_key`/`yandex_folder_id`
прямо в `config/app.yaml`).

`.env` (скопировать из `.env.example`):

| Переменная | Назначение |
|---|---|
| `YANDEX_FOLDER_ID` | id каталога в консоли Yandex Cloud |
| `YANDEX_API_KEY` | API-ключ сервисного аккаунта с ролью `ai.languageModels.user` |

Без ключей пайплайн не падает: каждая роль модели (структура, текст,
раскладка, имена ролей палитры, аудит по картинке) при отсутствии секретов
честно откатывается на детерминированный запасной вариант или, для
модельного аудита, возвращает явную причину `skipped_reason` вместо тишины.
Собрать презентацию `deckforge generate` можно и вовсе без `.env` — хуже по
содержанию текста, но без падений.

**Важно (проверено буквальным проходом по этому README):** `.env` сам по
себе файл ничего не подгружает — `scripts/run.sh` перед запуском API читает
его командой `source .env`, но `deckforge parse`/`generate`/`audit-visual`,
запущенные напрямую, ничего похожего не делают и видят только переменные,
уже присутствующие в окружении shell. Чтобы CLI реально пользовался моделью
(а не тихо откатывался на запасной вариант — деградация честная, но не
всегда то, что нужно), перед его запуском нужно явно подгрузить `.env` в
текущий shell:

```bash
set -a && source .env && set +a
```

Без этого шага `deckforge generate`/`audit-visual` всё равно отработают
(на запасных вариантах), просто заметно быстрее и без единого сетевого
вызова — не путайте это с настоящим прогоном на модели.

`web/.env.local.example` — только для случая, когда `pnpm dev` в `web/`
запускается отдельно от `scripts/run.sh` (тот сам прокидывает
`NEXT_PUBLIC_API_BASE`):

```
NEXT_PUBLIC_API_BASE=http://127.0.0.1:8000
```

LibreOffice на macOS без явного `FONTCONFIG_PATH` не видит системные шрифты
(в т.ч. шрифт шаблона) — `config/app.yaml` (`render.fontconfig_path`)
автопоиском находит `/opt/homebrew/etc/fonts`, но если рендер выходит не тем
шрифтом, задайте путь явно.

## Команды

Проверяйте точные аргументы через `--help` — они меняются быстрее, чем
документация:

```bash
uv run deckforge parse <шаблон.pptx> -o профиль.json
uv run deckforge generate <шаблон.pptx> <контент-пакет> -o <каталог> \
  [--variant dense|airy|visual] [--target-slides N] [--writer-max-workers N]
uv run deckforge audit-visual <шаблон.pptx> <колода.pptx> <содержание.json> \
  --content-pack <каталог>
```

- `parse` — разбирает шаблон в `TemplateProfile` (JSON), печатает в терминал
  «откуда что взято» и предупреждения о деградировавших источниках (сам
  профиль в файл, не в терминал — он велик).
- `generate` — весь путь от брифа до готовой презентации: структура →
  текст слайдов (параллельно) → все три варианта вёрстки → сборка со
  встроенным аудитом. Модельный аудит по картинке (C01–C11) в `generate` НЕ
  входит — команда печатает готовую команду `audit-visual` для следующего
  шага.
- `audit-visual` — детерминированный аудит (24 проверки) плюс модельный
  аудит по картинке (11 проверок, C01–C11) на уже собранном `.pptx`. Не
  пересобирает колоду и не вызывает модель для текста заново.
- `./scripts/run.sh` — поднимает API (FastAPI/uvicorn) на порту 8000 и
  веб-интерфейс (Next.js) на порту 3000 одной командой, сам делает
  `uv sync`/`pnpm install`, останавливает оба процесса по Ctrl+C.

Контент-пакет для `generate` — каталог с `brief.md` (YAML-фронтматтер
`pack`/`title`/`purpose`/`audience`/`language`/`target_slides` + сам бриф
Markdown-текстом) и `sources.md` (исходные материалы). Примеры — в
`fixtures/content-packs/`.

## Демонстрационный пакет (`submission/`)

Для промежуточной сдачи собирается один контент-пакет
(`fixtures/content-packs/queue-latency`) на трёх учебных шаблонах, по три
варианта вёрстки каждый (девять презентаций), плюс отдельно контрольный
`ЛЦТ2026 Шаблон презентации.pptx` (незнакомый файл, не использовался в
разработке) — десятая. Каждая выгружена в `.pptx`/`.pdf`/`.html` плюс
постраничные PNG-превью. Пакет не в git (сотни мегабайт, см. `.gitignore`),
воспроизводится локально:

```bash
set -a && source .env && set +a
uv run python scripts/build_submission.py \
  "dataset/templates/<шаблон>.pptx" \
  fixtures/content-packs/queue-latency \
  submission/<каталог-шаблона> \
  --variants dense airy visual \
  --stats-out scratchpad/stats/<шаблон>.json
```

(скрипт — тонкая обвязка над `deckforge generate` + `export.bundle.
export_bundle` на каждый вариант; сам генератор пакета собирается по
образцу `cli._cmd_generate`). Подробности — `submission/README.md` внутри
собранного пакета и `.superpowers/sdd/task-21-report.md`.

## Ограничения

- **SmartArt не создаётся по-настоящему.** Формат `dgm:` не поддержан ни
  `python-pptx`, ни LibreOffice — слайд разъехался бы при экспорте в PDF.
  Схемы (`compose/diagrams.py`) собираются из нативных автофигур и
  соединителей; в PowerPoint такие схемы редактируются как обычные фигуры,
  не как SmartArt-объект.
- **Встроенный в шаблон шрифт нельзя распаковать и поставить в систему**,
  если он упакован как EOT со сжатием MicroType Express — это закрытый
  формат сжатия, для которого нет открытого декодера. Если такого шрифта нет
  в системе, замер текста (укладка, аудит L03/L04/T02) идёт по метрически
  похожему шрифту, и это явно помечается в результате (`profile.warnings`),
  не молчит.
- **Картиночные и узорные заливки декора не переносятся в HTML-экспорт**
  (`export/html.py`) — HTML получает только то, что укладывается в CSS
  сплошной заливкой/текстом/растром слота.
- **Генерация изображений моделью не делалась** (пункт 3.1 ТЗ, задача со
  звёздочкой для топ-10) — вне объёма этой реализации.
- **Вместимость раскладки — площадная оценка**, не замер каждой буквы
  заранее: код меряет реальный текст уже уложенным (`compose/textfit.py`) и
  при переполнении меняет раскладку/кегль, но на этапе ВЫБОРА раскладки
  ориентируется на площадь, а не на точный текст, которого ещё нет. Находка
  аудита «текст не помещается» (L03/L04) поэтому остаётся частой даже на
  собранных этим пайплайном колодах.
- **Реестр заданий (`api/jobs.py`) живёт в памяти процесса API** —
  перезапуск API теряет прогресс текущих задач, но не уже собранные файлы на
  диске (`artifacts/`).
- **LibreOffice на этой машине не видит системные шрифты** без явного
  `FONTCONFIG_PATH=/opt/homebrew/etc/fonts` (см. «Переменные окружения»
  выше) — без него рендерит PDF/PNG другим шрифтом, чем шрифт шаблона.

## Обязательная проверка (что было пройдено буквально)

Прогон тестов дословно:

```
uv run pytest tests/ -v
```

`628 passed, 8 skipped, 2 warnings in 213.22s (0:03:33)` — восемь пропущенных
помечены `@pytest.mark.live` (ходят в сеть к живому провайдеру, требуют
`YANDEX_API_KEY`, не входят в обычный прогон, см. `pyproject.toml`,
`[tool.pytest.ini_options]`). Тесты границ слоёв и детерминированного аудита
входят в этот же прогон, отдельной команды для них нет (см.
[docs/AUDIT.md](docs/AUDIT.md)).

Команды `parse`/`generate`/`audit-visual`/`./scripts/run.sh` из раздела
«Команды» выше выполнены с чистого листа, с контрольным шаблоном `ЛЦТ2026
Шаблон презентации.pptx` (он намеренно не используется в тестах — играет
роль незнакомого файла с защиты) и контент-пакетом
`fixtures/content-packs/edu-platform`, с реальными ключами модели
(`set -a && source .env && set +a`, см. «Переменные окружения» выше) —
`generate` реально писала текст через `qwen3.6-35b-a3b` (структура 19.1с,
текст слайдов 102.3с, вся генерация 123.9с — порядок величины, что и в
таблице «Замеры», разброс — сетевая изменчивость живого вызова модели), а
`audit-visual` реально прогнала C01–C11 по картинке каждого слайда.
