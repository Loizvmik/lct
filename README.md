# DeckForge

Генератор презентаций по чужому шаблону (кейс VK Tech «Цифровой дизайнер
презентаций», ЛЦТ 2026). На вход: `.pptx`-шаблон, бриф, исходные материалы
текстом и, по желанию, фотографии. На выход: три варианта одной презентации в стиле шаблона,
каждый в `.pptx` (редактируемые текст, таблицы и графики), `.pdf` и `.html`,
с текстом для докладчика на каждом слайде и отчётом аудита.

Как устроено внутри: шаблон разбирается на дизайн-систему и раскладки,
снятые со слайдов-примеров; планировщик назначает раскладку каждому слайду
до того, как написан текст; модель пишет текст под пределы выбранной
раскладки; код собирает слайд клоном примера из шаблона и проверяет его
аудитом прямо в цикле сборки.

## Что умеет

Каждый тип содержания получается одним из двух путей: клоном раскладки,
снятой со слайда-примера шаблона, или, если такой раскладки нет или клон
не прошёл проверку, сборкой с нуля в стиле шаблона (его гарнитуры,
шкала кеглей, палитра, фон и декор).

| Содержание | Клон раскладки шаблона | С нуля в стиле шаблона |
|---|---|---|
| Заголовок, абзац, список, карточки | текст встаёт в места примера, лишние единицы повтора уходят со своим декором | заголовок кеглем и цветом заголовков примеров, текст не мельче body |
| График | родной `c:chart` примера с подменой данных; или рамка картинки-образца графика | нативный `c:chart` в палитре шаблона в самом крупном месте |
| Таблица | родная таблица примера | родная таблица на носителе: текстовой раскладке шаблона с лёгким декором |
| Показатели | раскладка вида `kpi`; «число + подпись» в одной фигуре примера двумя абзацами со своими кеглями | ряд крупных чисел кеглем display или h1 цветом бренда, подписи кеглем body (`compose/kpi.py`) |
| Цитата | раскладка вида `quote` | крупный текст h2 в кавычках, автор мелко, декоративная кавычка цветом акцента (`compose/quote.py`) |
| Команда | раскладка вида `team` | карточки «фото, имя, роль», без фото кружок с инициалами (`compose/team.py`) |
| Код | слайд кода шаблона: его плашка и моногарнитура | плашка цвета палитры с моногарнитурой шаблона или системной (`compose/code.py`) |
| Фото пользователя | подмена картинки примера в той же рамке (маска и скругление остаются) | фото на свободное место слайда |
| Схема, таймлайн | раскладка вида `timeline` | схема из нативных фигур и соединителей (`compose/diagrams.py`) |

Код на слайд идёт дословно из fenced-блоков источников (```` ```python ````),
модель пишет только заголовок и подпись. Числа графиков, таблиц и
показателей берутся из источников кодом, не моделью.

Сквозной контроль 28 сентября 2026 на всех четырёх шаблонах датасета с
набором `fixtures/content-packs/full-coverage` (все типы содержания и три
фото): в каждой презентации есть графики, таблицы, показатели, код,
цитата, команда и фото; три стиля за 30-70 с.

## Ограничения

- **Таймлайн не везде.** Раскладка-таймлайн берётся, только если она есть
  в шаблоне; иначе план по срокам идёт схемой или карточками.
- **Фото ставятся не все.** В сквозном контроле на слайдах 2 фото из 3 у
  VK Tech и VK Education, 1 из 3 у ЛЦТ2026. Фото не ставится, если
  раскладке слайда нечем его показать или распределение не нашло ему
  слайда; о каждом таком фото есть предупреждение с причиной.
- **Таблицы, нарисованные фигурами** (VK Tech, слайды 33-37), раскладкой
  таблицы не распознаются, и таблица строится без их оформления.
- **Код только из fenced-блоков** источников. Код, вставленный в текст
  без ограды, остаётся текстом; длинный фрагмент режется по строкам с «…».
- Прочие ограничения в
  [ARCHITECTURE.md](docs/ARCHITECTURE.md#известные-ограничения).

Документы:

- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): слои, разбор шаблона,
  планировщик, сборка, бюджет времени, поведение на незнакомом шаблоне,

- [docs/DEPLOY.md](docs/DEPLOY.md): установка на сервер с Ubuntu;
- [docs/SPEC.md](docs/SPEC.md): условия задачи и уточнения организаторов;
- [docs/TEST-INPUTS.md](docs/TEST-INPUTS.md): готовые входные данные.

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/), Node.js и
[pnpm](https://pnpm.io/), LibreOffice (`soffice`) и poppler (`pdftoppm`) для
PDF и превью. На Ubuntu всё ставит `scripts/setup_ubuntu.sh` (см.
[DEPLOY.md](docs/DEPLOY.md)).

```bash
cp .env.example .env      # вписать YANDEX_FOLDER_ID и YANDEX_API_KEY
./scripts/run.sh          # API на :8000, интерфейс на :3000
```

`run.sh` сам читает `.env`, ставит зависимости (`uv sync`, `pnpm install`),
поднимает FastAPI и Next.js и гасит оба по Ctrl+C. Порты меняются
переменными `API_PORT` и `WEB_PORT`.

Настройки пайплайна лежат в `config/` (версии в шапке каждого файла),
промпты в `agents/*/AGENT.md`. Секреты только в `.env`: если ключ окажется
в `config/app.yaml`, приложение откажется стартовать.

Без ключа всё работает запасными путями (типовой скелет структуры, текст
из пунктов плана, аудит по картинке пропускается с причиной). Для оценки
качества нужен ключ.

### Свой ключ Yandex AI Studio

Ключ можно не класть на сервер: каждый пользователь вставляет свой в
интерфейсе, «Настройки» → «Yandex AI Studio» (API-ключ и ID каталога),
кнопка «Проверить» делает короткий запрос к модели и говорит, что не так.
Ключ берётся в консоли Yandex Cloud: сервисный аккаунт с ролью
`ai.languageModels.user` → API-ключ; ID каталога на странице каталога.

Ключ хранится только в этом браузере (`localStorage`) и уходит на сервер
заголовками `X-Yandex-Api-Key`/`X-Yandex-Folder-Id` с загрузкой шаблона и
созданием заданий. Сервер держит его в памяти, пока идёт задание, и никуда
не пишет: ни в логи, ни в файлы результата. Без своего ключа работает ключ
из `.env`; если нет и его, интерфейс предупреждает над кнопкой создания.

## Как пользоваться

**Интерфейс** (`http://localhost:3000`):

1. Загрузить шаблон `.pptx`. Первый разбор незнакомого шаблона идёт
   90-280 с (модель смотрит раскладки), потом профиль берётся из кэша.
2. Ввести название, бриф и исходные материалы. Кнопки «Пример: заявки» и
   «Пример: учебная платформа» подставляют готовые входы из
   [TEST-INPUTS.md](docs/TEST-INPUTS.md).
3. По желанию добавить фотографии (до 10 за загрузку, до 10 МБ каждая,
   `.png` и `.jpg`) с подписями. Кнопка примера подставляет и фото его
   контент-пакета.
4. Запустить генерацию: три стиля идут тремя параллельными заданиями, у
   каждого свой прогресс по стадиям и свой бюджет 300 с.
5. В карточке варианта: время, режим прогона, оценки модели, верность
   шаблону, как собраны слайды. Статус «Готово с предупреждениями» значит,
   что файл есть, но что-то сделано запасным путём: предупреждения
   перечислены в карточке, в том числе каждое непоставленное фото с
   причиной. «Проверить вариант» открывает превью с
   находками аудита, починку выбранных находок и скачивание `.pptx`,
   `.pdf`, `.html`.

**Командная строка** (перед запуском `set -a; source .env; set +a`, иначе
CLI работает без модели):

```bash
# три стиля параллельно, общая структура
uv run deckforge generate "dataset/templates/Шаблон презентации VK Education.pptx" \
  fixtures/content-packs/queue-latency -o out/

# один стиль
uv run deckforge generate "dataset/templates/VK Tech шаблон.pptx" \
  fixtures/content-packs/edu-platform -o out/ --style visual

uv run deckforge parse <шаблон.pptx> -o profile.json        # только разбор
uv run deckforge audit-visual <шаблон> <deck.pptx> <deck.json> --content-pack <пакет>
uv run deckforge fidelity <шаблон> <deck.pptx> <deck.json>  # верность шаблону
uv run deckforge bench --pack fixtures/content-packs/queue-latency -o out/bench
uv run deckforge bench --compare out/bench/a.json out/bench/b.json
```

Контент-пакет для CLI: каталог с `brief.md` (YAML-шапка `title`,
`purpose`, `audience`, `language`, `target_slides` и текст брифа),
`sources.md` и необязательной папкой `photos/` (подпись к фото в
`<имя>.txt` рядом). Примеры в `fixtures/content-packs/`; `full-coverage`
содержит все типы содержания: ряды для графиков, таблицу, показатели,
фрагмент кода на Python, цитату, команду и три фото.

**API.** Фото загружаются `POST /api/photos` (multipart, поля `files` и
`captions`) и передаются в задание полем `photos: [{photo_id, caption}]`
у `POST /api/decks` и `POST /api/decks/batch`. `POST
/api/examples/{name}/photos` загружает фото контент-пакета примера.
Шаблон принимается до 150 МБ.

`deckforge bench` гоняет шаблоны × наборы × стили тем же путём, что
`generate`, и пишет одну таблицу чисел (время, режим, клоны, находки по
серьёзности, оценки по картинке, верность шаблону, энтропия раскладок,
редактируемость, вызовы модели, ожидание очереди) в markdown и JSON.
`--offline` даёт нижнюю планку без модели, `--compare` показывает дельты
двух прогонов.

## Что на выходе

На каждый стиль (`artifacts/api/decks/<задание>/<стиль>/`):

- `deck.pptx`: слайды на макетах шаблона, нативные текст, таблицы и
  диаграммы (`c:chart` с данными внутри), фото в рамках шаблона. Текст для
  докладчика в заметках слайда. В `docProps/custom.xml` записаны версии
  всех промптов и конфигов, которыми собран файл;
- `deck.pdf` и `preview/*.png` через LibreOffice;
- `deck.html`: веб-версия слайдов и отчёт (находки аудита, оценки модели,
  риск-отбор, режим и секунды по стадиям, вызовы модели, верность шаблону,
  путь сборки каждого слайда);
- `deck.json`: план колоды (раскладка, текст, запасные раскладки, путь по
  лестнице сборки).

## Три варианта

Стиль задаёт целевую функцию планировщика раскладок (`config/styles.yaml`),
а не перекраску готового текста. Текст каждого стиля пишется под его
раскладки, структура общая.

Чтобы варианты различались глазом, а не только словами:

- стиль перестраивает структуру до планирования (`pattern/shape.py`):
  dense сливает простые пункты и берёт 4-6 единиц на слайд, airy не больше
  трёх, visual делает график из каждого числового ряда источника;
- стили пакета планируют по очереди dense, airy, visual, и каждый платит
  штраф `batch_overlap: 60` за облик раскладки, который сосед уже поставил
  на тот же пункт содержания (`PlanShare` в `api/jobs.py`);
- различимость считается (`pattern/distinct.py`): доля пунктов с одним
  обликом у каждой пары стилей, цель не выше 0,4. Сводка в поле
  `distinct` снимка задания и в выводе CLI.

| Стиль | Предпочитает раскладки | Плотность | Слов на единицу | Особенности |
|---|---|---|---|---|
| `dense` | таблицы, карточки, две колонки, показатели, списки | 0,80 | 16 | больше фактов на слайде |
| `airy` | разделители, цитаты, показатель с подписью, редкие карточки | 0,50 | 9 | разделители между разделами |
| `visual` | фото, фото с текстом, графики, схемы, карточки | 0,55 | 10 | вдвое ценит декор шаблона и графики |

## Время

Лимит ТЗ: 5 минут на одну презентацию, разбор шаблона в него не входит.
Замер 28 сентября на прогретом кэше: три стиля параллельно за 30-70 с.
Если время поджимает, задание переходит в режим FAST или EMERGENCY и
жертвует необязательными стадиями (сокращение текста моделью, аудит по
картинке), а не файлом. Подробности в
[ARCHITECTURE.md](docs/ARCHITECTURE.md#бюджет-времени-и-очередь-модели).

## Тесты

```bash
uv run pytest -q       # 1276 тестов, 6-7 минут
```

Модель в тестах не вызывается. В набор входят проверки границ слоёв и
проверка, что в Python нет зашитых промптов.
