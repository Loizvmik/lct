# DeckForge

Генератор презентаций по чужому шаблону (кейс VK Tech «Цифровой дизайнер
презентаций», ЛЦТ 2026). На вход: `.pptx`-шаблон, бриф и исходные материалы
текстом. На выход: три варианта одной презентации в стиле шаблона,
каждый в `.pptx` (редактируемые текст, таблицы и графики), `.pdf` и `.html`,
с текстом для докладчика на каждом слайде и отчётом аудита.

Как устроено внутри: шаблон разбирается на дизайн-систему и раскладки,
снятые со слайдов-примеров; планировщик назначает раскладку каждому слайду
до того, как написан текст; модель пишет текст под пределы выбранной
раскладки; код собирает слайд клоном примера из шаблона и проверяет его
аудитом прямо в цикле сборки.

Документы:

- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): слои, разбор шаблона,
  планировщик, сборка, бюджет времени, поведение на незнакомом шаблоне,
  известные ограничения;
- [docs/MODELS.md](docs/MODELS.md): сервис, модель, настройки по ролям,
  число вызовов на презентацию;
- [docs/AUDIT.md](docs/AUDIT.md): все проверки, пороги, автопочинка, аудит
  по картинке, метрики верности шаблону;
- [docs/DEPLOY.md](docs/DEPLOY.md): установка на сервер с Ubuntu;
- [docs/SPEC.md](docs/SPEC.md): условия задачи и уточнения организаторов;
- [docs/TEST-INPUTS.md](docs/TEST-INPUTS.md): готовые входные данные.

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/), Node.js и
[pnpm](https://pnpm.io/), LibreOffice (`soffice`) и poppler (`pdftoppm`) для
PDF и превью. На Ubuntu всё ставит `scripts/setup_ubuntu.sh` (см.
[DEPLOY.md](docs/DEPLOY.md)).

```bash
cp .env.example .env      # вписать YANDEX_FOLDER_ID и YANDEX_API_KEY
./scripts/run.sh          # API на :8000, интерфейс на :3000
```

`run.sh` сам читает `.env`, ставит зависимости (`uv sync`, `pnpm install`),
поднимает FastAPI и Next.js и гасит оба по Ctrl+C. Порты меняются
переменными `API_PORT` и `WEB_PORT`.

Настройки пайплайна лежат в `config/` (версии в шапке каждого файла),
промпты в `agents/*/AGENT.md`. Секреты только в `.env`: если ключ окажется
в `config/app.yaml`, приложение откажется стартовать.

Без ключа всё работает запасными путями (типовой скелет структуры, текст
из пунктов плана, аудит по картинке пропускается с причиной). Для оценки
качества нужен ключ.

## Как пользоваться

**Интерфейс** (`http://localhost:3000`):

1. Загрузить шаблон `.pptx`. Первый разбор незнакомого шаблона идёт
   90-280 с (модель смотрит раскладки), потом профиль берётся из кэша.
2. Ввести название, бриф и исходные материалы. Кнопки «Пример: заявки» и
   «Пример: учебная платформа» подставляют готовые входы из
   [TEST-INPUTS.md](docs/TEST-INPUTS.md).
3. Запустить генерацию: три стиля идут тремя параллельными заданиями, у
   каждого свой прогресс по стадиям и свой бюджет 300 с.
4. В карточке варианта: время, режим прогона, оценки модели, верность
   шаблону, как собраны слайды. «Проверить вариант» открывает превью с
   находками аудита, починку выбранных находок и скачивание `.pptx`,
   `.pdf`, `.html`.

**Командная строка** (перед запуском `set -a; source .env; set +a`, иначе
CLI работает без модели):

```bash
# три стиля параллельно, общая структура
uv run deckforge generate "dataset/templates/Шаблон презентации VK Education.pptx" \
  fixtures/content-packs/queue-latency -o out/

# один стиль
uv run deckforge generate "dataset/templates/VK Tech шаблон.pptx" \
  fixtures/content-packs/edu-platform -o out/ --style visual

uv run deckforge parse <шаблон.pptx> -o profile.json        # только разбор
uv run deckforge audit-visual <шаблон> <deck.pptx> <deck.json> --content-pack <пакет>
uv run deckforge fidelity <шаблон> <deck.pptx> <deck.json>  # верность шаблону
uv run deckforge bench --pack fixtures/content-packs/queue-latency -o out/bench
uv run deckforge bench --compare out/bench/a.json out/bench/b.json
```

Контент-пакет для CLI: каталог с `brief.md` (YAML-шапка `title`,
`purpose`, `audience`, `language`, `target_slides` и текст брифа),
`sources.md` и необязательной папкой `photos/`. Примеры в
`fixtures/content-packs/`. Фотографии пользователя принимает только CLI:
интерфейс и API их пока не загружают.

`deckforge bench` гоняет шаблоны × наборы × стили тем же путём, что
`generate`, и пишет одну таблицу чисел (время, режим, клоны, находки по
серьёзности, оценки по картинке, верность шаблону, энтропия раскладок,
редактируемость, вызовы модели, ожидание очереди) в markdown и JSON.
`--offline` даёт нижнюю планку без модели, `--compare` показывает дельты
двух прогонов.

## Что на выходе

На каждый стиль (`artifacts/api/decks/<задание>/<стиль>/`):

- `deck.pptx`: слайды на макетах шаблона, нативные текст, таблицы и
  диаграммы (`c:chart` с данными внутри), фото в рамках шаблона. Текст для
  докладчика в заметках слайда. В `docProps/custom.xml` записаны версии
  всех промптов и конфигов, которыми собран файл;
- `deck.pdf` и `preview/*.png` через LibreOffice;
- `deck.html`: веб-версия слайдов и отчёт (находки аудита, оценки модели,
  риск-отбор, режим и секунды по стадиям, вызовы модели, верность шаблону,
  путь сборки каждого слайда);
- `deck.json`: план колоды (раскладка, текст, запасные раскладки, путь по
  лестнице сборки).

## Три варианта

Стиль задаёт целевую функцию планировщика раскладок (`config/styles.yaml`),
а не перекраску готового текста. Текст каждого стиля пишется под его
раскладки, структура общая.

| Стиль | Предпочитает раскладки | Плотность | Слов на единицу | Особенности |
|---|---|---|---|---|
| `dense` | таблицы, карточки, две колонки, показатели, списки | 0,80 | 16 | больше фактов на слайде |
| `airy` | разделители, цитаты, показатель с подписью, редкие карточки | 0,50 | 9 | разделители между разделами |
| `visual` | фото, фото с текстом, графики, схемы, карточки | 0,55 | 10 | вдвое ценит декор шаблона и графики |

## Время

Лимит ТЗ: 5 минут на одну презентацию, разбор шаблона в него не входит.
Замер 27 сентября на прогретом кэше: три стиля параллельно за 60-70 с.
Если время поджимает, задание переходит в режим FAST или EMERGENCY и
жертвует необязательными стадиями (сокращение текста моделью, аудит по
картинке), а не файлом. Подробности в
[ARCHITECTURE.md](docs/ARCHITECTURE.md#бюджет-времени-и-очередь-модели).

## Тесты

```bash
uv run pytest -q       # 1066 тестов, 6-7 минут
```

Модель в тестах не вызывается. В набор входят проверки границ слоёв и
проверка, что в Python нет зашитых промптов.
